==============================================================
 AJNA TERAPIAS - COMANDOS PARA RODAR O SITE
==============================================================
Todos os comandos são digitados no PowerShell, dentro da pasta
do projeto (ajnaterapias).


--------------------------------------------------------------
 JEITO RÁPIDO (faz tudo sozinho)
--------------------------------------------------------------
Primeira vez (cria o ambiente, o .env e o administrador):

    powershell -ExecutionPolicy Bypass -File .\iniciar.ps1 -Admin

Nas próximas vezes (só liga o site):

    powershell -ExecutionPolicy Bypass -File .\iniciar.ps1

Depois abra no navegador:  http://127.0.0.1:5000/login
Para desligar o servidor:  Ctrl + C


--------------------------------------------------------------
 PASSO A PASSO (o que o iniciar.ps1 faz por dentro)
--------------------------------------------------------------
1) Criar o ambiente virtual (só na primeira vez)
    py -m venv .venv

2) Instalar as dependências
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt

3) Criar o arquivo de configuração (só na primeira vez)
    Copy-Item docs/.env.example .env
   Depois abra o .env e troque a SECRET_KEY por uma gerada com:
    .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"

4) Criar ou atualizar o administrador
    .\.venv\Scripts\python.exe backend\seed_admin.py

5) Ligar o site
    .\.venv\Scripts\python.exe backend\run.py

Rodar os testes automáticos:
    cd backend; ..\.venv\Scripts\python.exe -m pytest tests; cd ..


--------------------------------------------------------------
 CONFIGURAÇÃO: LOCAL x WEB  (só isto muda)
--------------------------------------------------------------
Os valores ficam no arquivo .env (no seu computador) ou nas
"Environment Variables" do serviço de hospedagem (na web).
Os comandos e o código são os mesmos nos dois casos.

    Variável                LOCAL               WEB
    ---------------------   -----------------   ------------------------
    FLASK_ENV               development         production
    SECRET_KEY              chave gerada        OUTRA chave gerada, longa
    HOST                    127.0.0.1           0.0.0.0
    PORT                    5000                o hospedeiro define
    SESSION_COOKIE_SECURE   false               true  (exige HTTPS)
    DATABASE_URL            (vazio = SQLite)    postgresql://... (Neon/Supabase)

Na web (ex.: Render, plano grátis):
  - Comando de build:  pip install -r requirements.txt
  - Comando de start:  python backend/run.py   (já está no Procfile)
  - Coloque DATABASE_URL nas Environment Variables.
  - Depois do primeiro deploy, crie o admin pelo "Shell" do serviço
    (ou do seu PC, com o mesmo DATABASE_URL no .env):
        python backend/seed_admin.py


--------------------------------------------------------------
 ADMINISTRADORA PRINCIPAL ("chave primária")
--------------------------------------------------------------
É a conta que APROVA, por e-mail, qualquer alteração de login de
administrador (dela ou de outro admin) e recebe os avisos de segurança.
Hoje: Ellen Robinson. Para trocar ou definir de novo:
    .\.venv\Scripts\python.exe backend\seed_admin.py --principal


--------------------------------------------------------------
 E-MAIL: CONFIRMAR ALTERAÇÃO DO LOGIN DO ADMINISTRADOR
--------------------------------------------------------------
No painel: "Minha conta" -> altere nome, e-mail, telefone e/ou senha,
digite a SENHA ATUAL e clique em "Enviar confirmação por e-mail".
O link vai para o e-mail da ADMINISTRADORA PRINCIPAL. Só ao clicar
nele (até 30 minutos) a alteração é aplicada.


--------------------------------------------------------------
 ESQUECI MINHA SENHA (clientes e administradores)
--------------------------------------------------------------
Na tela de login: "Esqueci minha senha" -> digita o e-mail -> recebe
um link (30 min, uso único) -> cria a nova senha.
  - Clientes: mínimo 8 caracteres. Administradores: mínimo 12.
  - Se um administrador redefinir a senha, a principal recebe um aviso.
  - A resposta é sempre a mesma, exista ou não o e-mail (não revela
    quem tem cadastro), e há um intervalo de 2 min entre pedidos.

Sem SMTP configurado (padrão): o e-mail NÃO é enviado; ele é salvo em
    backend\instance\outbox\   (abra o .eml com o Outlook ou o Bloco de Notas
                                e copie o link "confirm?token=...")

Para ENVIAR de verdade pelo Gmail (grátis):
1) Na conta Google que vai ENVIAR os e-mails, ative a
   "Verificação em duas etapas" (myaccount.google.com -> Segurança).
2) Acesse myaccount.google.com/apppasswords, crie uma senha de app
   chamada "Ajna site" e copie as 16 letras.
3) No .env, descomente e preencha:
     SMTP_HOST=smtp.gmail.com
     SMTP_PORT=587
     SMTP_USER=conta.que.envia@gmail.com
     SMTP_PASSWORD=as16letrasdasenhadeapp
     MAIL_FROM=Ajna Terapias <conta.que.envia@gmail.com>
4) Reinicie o site (Ctrl+C e ligue de novo).
Na web, coloque as mesmas variáveis no host e BASE_URL=https://seudominio.


--------------------------------------------------------------
 FASE ATUAL: TUDO LOCAL (SQLite + DBeaver)
--------------------------------------------------------------
Enquanto não houver hospedagem, o projeto usa SOMENTE o banco local:
  - Arquivo: backend\instance\ajna.db
  - No .env, a linha DATABASE_URL fica COMENTADA (com # na frente).

Ver/editar no DBeaver:
  Nova conexão -> SQLite -> Path: (caminho completo do projeto)\backend\instance\ajna.db
  Não edite a coluna password_hash à mão.


--------------------------------------------------------------
 QUANDO COMPRAR O HOST: MIGRAR PARA POSTGRESQL
--------------------------------------------------------------
1) Crie o PostgreSQL (Neon, Supabase ou o do próprio host).
2) No .env, descomente e preencha:  DATABASE_URL=postgresql://...
3) Simule (não grava nada, só mostra quantos registros vão):
     .\.venv\Scripts\python.exe backend\migrate_to_postgres.py --simular
4) Migre de verdade:
     .\.venv\Scripts\python.exe backend\migrate_to_postgres.py
5) Coloque o mesmo DATABASE_URL nas Environment Variables do host.
6) No DBeaver, crie uma conexão PostgreSQL para conferir os dados.

O ajna.db não é apagado: fica como backup.
A migração se recusa a rodar se o PostgreSQL já tiver usuários.


--------------------------------------------------------------
 POSTGRESQL GRÁTIS E SEMPRE ATIVO (NEON)
--------------------------------------------------------------
1) Crie uma conta grátis em https://neon.tech
2) Crie um projeto (região: AWS São Paulo, se houver).
3) No painel, clique em "Connect" e copie o connection string.
   Ele se parece com:
     postgresql://usuario:senha@ep-xxxx.sa-east-1.aws.neon.tech/neondb?sslmode=require
4) Cole no .env:
     DATABASE_URL=postgresql://...
5) Crie o admin NO BANCO ONLINE:
     .\.venv\Scripts\python.exe backend\seed_admin.py
6) Ligue o site normalmente. As tabelas são criadas sozinhas.

Para voltar ao SQLite local: comente a linha DATABASE_URL no .env.

Alternativa: Supabase (https://supabase.com) → Project Settings →
Database → Connection string (URI). No plano grátis ele PAUSA após
7 dias sem uso; o Neon só "dorme" e acorda sozinho.

ATENÇÃO: os dados do SQLite e do PostgreSQL são separados. Clientes
criados num não aparecem no outro.
